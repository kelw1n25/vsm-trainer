# Сценарии

Сценарий — интерактивная визуальная новелла в YAML-файле в `backend/scenarios/`. Имя файла совпадает с `id`.
При старте backend проверяет каждый файл и загружает корректные в БД. Файл с ошибками пропускается
с понятным списком ошибок в логе, а в БД остаётся его прошлая корректная версия — опечатка не ломает демонстрацию.

Содержание сценариев построено на материалах кейсодержателя: 51 ситуация из «Примеров ситуаций взаимодействия
поездного персонала с пассажирами», ролевая модель общения и стандарты СТО РЖД 03.011, 03.013, 03.014.
Эти материалы лежат в `backend/config/handbook.yaml` и доступны в приложении в разделе «Справочник».
Тест `test_every_handbook_situation_is_trained` проверяет, что каждая из 51 ситуации отрабатывается
хотя бы в одном сценарии.

JSON-схема формата: `GET /api/scenarios/schema` (генерируется из тех же классов, что и проверка).

## Как устроена история

Сценарий — граф узлов. Узел — это **сцена** (фон и до трёх персонажей) с **диалогом** и моментом **решения**
или **финалом**:

```
сцена → реплики, мысли проводника, слова рассказчика → варианты (таймер идёт только с этого момента)
      → выбор → реакция персонажей → следующая сцена … → финал с названием
```

Выбор меняет две шкалы из ТЗ (видны игроку), **скрытые параметры** (доверие, напряжение — не видны,
но открывают и закрывают ветки), **флаги** и очки компетенций. Правильный ответ во время игры не
подсказывается: пояснения и лучший вариант показываются только в разборе после финала.

## Формат

```yaml
id: business-seat-conflict           # латиница, цифры, «-» и «_»; совпадает с именем файла
title: Два пассажира на одно место
category: conflict                   # conflict | medical | service | safety
difficulty: 2                        # 1–3, множитель XP
service_class: Бизнес                # Первый | Бизнес | Комфорт | Стандарт — из справочника
route: Москва — Санкт-Петербург
description: Короткое описание без спойлеров развилок
situations: [33, 13, 9, 8, 23]       # номера ситуаций из справочника — по ним строится разбор
initial: {loyalty: 60, safety: 90}   # стартовые значения шкал 0–100
stats: {trust: 40, tension: 40}      # скрытые параметры и их стартовые значения
characters:                          # персонажи; проводник (player) и рассказчик (narrator) — встроенные
  sergey:
    name: Сергей Андреевич
    role: Пассажир
    look: {top: "#56657F", bottom: "#34405A", hair: "#2B2320"}   # outfit: uniform — форма сотрудника
start_node: start

nodes:
  - id: start
    scene:
      background: business           # salon | salon_evening | salon_night | business | platform | vestibule | bistro | staff_room
      characters:
        - {id: player, position: left}
        - {id: sergey, position: right, expression: annoyed, hand: point, item: ticket}
        # pose: stand | sit | wheelchair — сидит в кресле поезда или в коляске, как на картинке сценария
        # hand: down | point | hold | radio | hush | chest | throat; item: ticket | bottle | cup | extinguisher | radio
    situation: Кратко для разбора и аналитики
    dialogue:
      - {speaker: narrator, text: "Бизнес-класс, третий вагон."}
      - {speaker: sergey, text: "В моём кресле сидит женщина.", expression: angry}   # эмоция меняется по реплике
      - {speaker: player, thought: true, text: "Не занимать ничью сторону."}         # мысль проводника
      - {speaker: sergey, text: "Ладно, проверяйте.", sound: sigh_male}              # звук вместе с репликой
    timer_seconds: 20                # необязательно; только вместе с timeout_next
    timeout_next: argument
    timeout_effects: {loyalty: -15}  # обязан снижать хотя бы одну шкалу
    timeout_reaction:                # что произошло из-за промедления
      - {speaker: narrator, text: "Спор слышен в соседнем вагоне."}
    choices:
      - id: check_both
        text: "«Давайте решим вопрос спокойно. Позвольте ваши билеты»"
        condition: ["trust >= 50", "flag chief_called"]   # необязательно; все условия через «И»
        effects:
          loyalty: 10
          safety: 0
          stats: {trust: 15, tension: -15}
          set_flags: [tickets_checked]
          competences: {communication: 10, service: 5}
        reaction:                    # реакция персонажей сразу после выбора
          - {speaker: sergey, text: "Пожалуйста, вот."}
        next: tickets_checked
        best: true                   # ровно один лучший вариант в узле — только для разбора
        explanation: Почему решение так влияет и как можно было лучше

  - id: end_success                  # финал: outcome, название и итог, без вариантов
    scene: {background: business, characters: [{id: player, position: left, expression: happy}]}
    outcome: success                 # success | partial | failure
    ending: Оба пассажира довольны
    final_text: Сбой продажи урегулирован без спора.
    dialogue: [{speaker: narrator, text: "Эпилог — необязательно."}]
```

Звуки реплик: `sigh` и `sigh_long` — выдох без голоса (подходит любому персонажу), `sigh_male` — мужской вздох.
Во всех сценариях очень тихо играет фоновая музыка, а пока печатается реплика, звучат короткие щелчки «голоса» своей высоты у каждого персонажа. Игрок может выключить звук кнопкой «Звук».

Эмоции персонажей: `neutral`, `happy`, `angry`, `annoyed`, `worried`, `sad`, `surprised`, `thinking`,
`serious`, `pained`, `tipsy`. Коды компетенций задаются в `backend/config/game.yaml`: `communication`,
`first_aid`, `safety_rules`, `service`, `stress_resistance`.

### Условия показа варианта (скрытые ветки)

| Запись | Смысл |
|--------|-------|
| `safety >= 40` | шкала безопасности не меньше 40 (операторы `>=`, `<=`, `>`, `<`, `==`) |
| `trust >= 50` | скрытый параметр «доверие» не меньше 50 — пассажир расскажет больше или согласится на решение |
| `tension < 50` | напряжение невысокое — можно мягко переключить разговор |
| `flag pet_in_carrier` | ранее установлен флаг |
| `not flag conflict_started` | флаг не установлен |

## Что проверяет валидатор

- поля, типы и диапазоны; неизвестное поле — ошибка (опечатка `timout_next` не пройдёт молча);
- нет переходов в несуществующие узлы и недостижимых узлов, из каждого узла есть путь до финала;
- условия записаны корректно, флаги из условий где-то устанавливаются, а шкалы и скрытые параметры объявлены;
- персонажи сцены объявлены в `characters`, говорит только тот, кто стоит в сцене (или рассказчик и проводник);
- мысли (`thought: true`) бывают только у проводника; у решения есть диалог, у финала — название;
- класс обслуживания и номера ситуаций есть в справочнике;
- коды компетенций есть в конфиге, у таймера есть `timeout_next`, и истечение реально штрафует;
- в каждом узле ровно один `best: true`; узел не может оказаться тупиком из-за условий.

Ошибки называют узел и вариант по их `id`:

```
✗ lost-child.yaml
    - узел «announcement», вариант «no_personal_data», reaction: говорит «pavel», но его нет в сцене (scene.characters)
```

## Как добавить развилку за 5 минут

Пример: в сценарии «Два пассажира на одно место» добавить скрытый вариант — «попросить пассажиров
самих договориться», который виден, только если напряжение уже спало.

1. Откройте `backend/scenarios/business-seat-conflict.yaml`, узел `tickets_checked`, и добавьте вариант:

   ```yaml
         - id: let_them_agree
           text: Предложить пассажирам самим договориться, кто пересядет
           condition: ["tension < 30"]
           effects:
             loyalty: -5
             stats: {tension: 10}
             competences: {communication: -5}
           reaction:
             - {speaker: lyudmila, text: "То есть решать должны мы?"}
           next: chief_resolves
           explanation: Сбой продажи решает начальник поезда — перекладывать решение на пассажиров нельзя.
   ```

2. Проверьте файл без перезапуска:

   ```bash
   docker compose exec backend python -m app.scenarios.validator
   ```

3. Примените изменения: `docker compose restart backend`.

Новый вариант появится в игре, разборе, аналитике и архиве веток. Код менять не нужно: каталог
`backend/scenarios` подключён к контейнеру с диска. Новый сценарий добавляется так же — файлом
`<id>.yaml`; проводникам придёт уведомление «Новый сценарий».

## Как изменить правило шкалы

Правила шкал лежат в данных, а не в коде:

| Что меняем | Где |
|------------|-----|
| Стартовые значения лояльности и безопасности | `initial` в файле сценария |
| Как решение сдвигает шкалы | `effects.loyalty` / `effects.safety` варианта |
| Цена промедления под таймером | `timeout_effects` узла |
| Вес итоговых шкал в XP | `scoring.scale_weights` в `backend/config/game.yaml` |
| Досрочный провал при нуле любой шкалы | движок, `engine/service.py: _advance` — единственное правило в коде |

Пример: сделать промедление в споре «Два пассажира на одно место» опаснее — пусть оно бьёт и по
безопасности. В `business-seat-conflict.yaml`, узел `argument`:

```yaml
    timeout_effects: {loyalty: -15, safety: -10, stats: {tension: 20}}
```

Проверка и применение — те же два шага: `docker compose exec backend python -m app.scenarios.validator`,
затем `docker compose restart backend`. Изменение сразу видно в игре (шкала на панели), в разборе
(«Время истекло» с новой дельтой) и в аналитике.

### Пример прохождения: «Два пассажира на одно место»

1. **Старт.** Сергей Андреевич с билетом на 5А, в кресле — Людмила. Проверить оба билета →
   доверие растёт; встать на сторону одного или отослать в тамбур → спор.
2. **Спор (таймер 20 с).** Развести пассажиров — к проверке билетов; окрик — финал «Скандал в бизнес-классе»;
   промедление — начальник поезда приходит на шум, лояльность −15.
3. **Билеты проверены.** Оба действительны — сбой продажи. Пригласить начальника поезда; при доверии ≥ 50
   открывается вариант заранее подобрать место; «кто первый сел» — финал «Жалоба на несправедливое решение».
4. **Начальник поезда.** Пересадка без доплаты; Людмила просит повышение класса. Уточнить места и доплату
   по правилам — «Оба пассажира довольны»; пообещать без проверки или отказать — «Места распределены, но осадок остался».
