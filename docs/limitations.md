# Ограничения и план развития

## Ограничения текущей версии

### Контент и данные
- **Сценарии — демо-контент.** Все пять сценариев написаны командой до получения материалов
  кейсодержателя и помечены `demo: true`. Алгоритмы первой помощи и действий при подозрительном
  предмете упрощены и должны быть сверены с регламентами перевозчика.
- **Данные синтетические.** Сотрудники, бригады, депо и история созданы генератором `app/seed.py`.
  У демо-учёток общий пароль и один хеш пароля на всех — это допустимо только для демо.
- **Удаление файла сценария** не удаляет сценарий из БД: на него ссылаются прохождения.
  Нужен признак «архивный».
- PyYAML не сообщает о **повторяющихся ключах** в YAML: побеждает последний. Валидатор ловит
  дубли `id` узлов и вариантов, но не дубли полей.

### Безопасность
- **Нет SSO.** Сотрудники, созданные через HR API, не могут войти по паролю.
- **JWT хранится в `localStorage`** — уязвим к XSS. Для продакшена — httpOnly cookie и refresh-токены.
- **Нет ограничения частоты запросов** на вход и интеграционный API.
- **Один API-ключ интеграции** на все внешние системы, без разграничения прав.

### Эксплуатация
- **Frontend работает на dev-сервере Vite.** Для продакшена — сборка `npm run build`
  и раздача статики через nginx.
- **Миграции применяются при старте backend.** При нескольких копиях это безопасно
  (Alembic проверяет версию), но правильнее вынести миграции в отдельный шаг деплоя.
- **Сгорание баллов применяется при запросах** уведомлений и рейтинга, фоновых задач нет.
  Сотрудник, которого никто не запрашивает, «сгорает» при первом таком запросе. Для отчётов
  в реальном времени нужен планировщик.
- **Уведомления приходят опросом** раз в 30 секунд, без push и WebSocket.
- **Часовой пояс календарных периодов** (неделя, месяц, челлендж) — Москва, зашит в код.
- **Правила «типичных ошибок»** — эвристики с порогами (например, 30% таймаутов). Пороги
  нужно откалибровать на реальных данных вместе с инструкторами.
- **Тесты требуют PostgreSQL**; в репозитории нет CI.

## План развития после хакатона

1. **Контент.** Заменить демо-сценарии материалами кейсодержателя, добавить маршруты и классы
   обслуживания; редактор сценариев для методистов с визуализацией графа и валидацией «на лету».
2. **Интеграции.** SSO (корпоративный вход), выгрузка результатов в LMS по стандарту xAPI,
   вебхуки для HR о повышении уровня и ачивках, ключи API на каждую систему с правами.
3. **Обучение.** Адаптивная сложность (таймеры короче для опытных), обязательные сценарии от
   инструктора с дедлайном, командные челленджи бригад, повторение сценариев с ошибками
   по интервалам.
4. **Аналитика для руководства.** Дашборд депо и компании: карта компетенций, динамика,
   «проблемные» узлы сценариев, где ошибаются чаще всего.
5. **Реализм.** Озвучка реплик, фото и схемы вагонов, мобильная версия для планшета проводника,
   офлайн-режим в поездке.
6. **Эксплуатация.** nginx для статики, миграции в CI/CD, планировщик для сгорания и
   уведомлений, мониторинг и логирование, нагрузочное тестирование.
