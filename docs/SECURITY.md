# Безопасность и 152-ФЗ

## Данные

- **Только синтетические данные.** Сотрудники, бригады, депо и история прохождений создаются генератором
  `backend/app/seed.py` из списков имён — это не реальные люди. В сценариях пассажиры обозначены ролями
  и вымышленными именами; телефонов, email, документов и медицинских данных нет нигде.
- **Аватар — без фотографий.** Профиль настраивается конструктором из деталей формы (`app/profiles/avatar.py`):
  сервер хранит три кода из фиксированных списков, а изображение лица сотрудника не загружается и не хранится.
- **В журналы не пишутся ПДН.** JSON-журнал (`app/observability.py`) содержит метод, путь, статус, длительность
  и `request_id`; аудит входов — внутренний `employee_id` и IP. Неудачный вход пишется без табельного номера.
  События аналитики содержат идентификаторы узлов и вариантов, а не ФИО.
- **На устройстве — минимум.** Мобильные клиенты хранят токены и кэш последних ответов экранов. При выходе
  и при истечении сессии кэш удаляется. Android: `allowBackup=false` и `data_extraction_rules` — сессия и кэш
  не попадают в облачные копии; iOS: Keychain-запись `ThisDeviceOnly` не переносится на другие устройства.

## Секреты

- В Git нет секретов: `.env` в `.gitignore`, в `.env.example` — только демо-значения с пометкой «replace-me».
- `JWT_SECRET` и `INTEGRATION_API_KEY` не короче 32 символов — иначе backend не стартует (`app/config.py`).
- Мобильные приложения не содержат ключей: адрес API задаётся при сборке (`API_BASE_URL`).

## Аутентификация и авторизация

| Мера | Где |
|------|-----|
| Пароли — scrypt с солью, сравнение за постоянное время | `app/auth/security.py` |
| Access JWT HS256 на 12 ч + refresh-токен на 30 дней, в БД — только SHA-256 | `app/auth/tokens.py` |
| Ротация refresh-токена; повтор обменянного токена отзывает все сессии сотрудника | `tokens.rotate` |
| Выход отзывает сессию устройства | `POST /api/auth/logout` |
| Лимит неудачных входов: 5 на номер, 20 на IP за 15 минут → `429` + `Retry-After` | `app/auth/rate_limit.py` |
| Роли: проводник видит только свои данные, инструктор — своё депо | `app/auth/deps.py`, проверки владельца в роутерах |
| Интеграции — отдельный ключ `X-API-Key`, JWT пользователей к ним не подходит | `app/integration/router.py` |

Лимит входа хранится в памяти процесса: при нескольких копиях backend он действует на каждую копию.
Для продакшена — общий счётчик (Redis) или лимит на балансировщике.

## Транспорт

- iOS: App Transport Security — только HTTPS; исключение `NSAllowsLocalNetworking` разрешает HTTP лишь
  к локальной сети для разработки на симуляторе.
- Android: `network_security_config` запрещает HTTP; отладочная сборка разрешает его только для `10.0.2.2`
  и `localhost` (`src/debug/res/xml`), в release-сборку это исключение не попадает.
- Release-сборки обоих приложений по умолчанию указывают на HTTPS-адрес.

## Ошибки и некорректные действия

- Единый формат `{"detail": {"code", "message"}}`; неизвестная ошибка — `500 internal_error` без стека
  и деталей реализации, с `request_id` для поддержки.
- Сервер отклоняет: ответ после таймера (`time_expired`), повтор или ответ на старый шаг (`stale_node`),
  ответ без показа вариантов (`choices_not_shown`), скрытый условием или чужой вариант (`unknown_choice`),
  чужое прохождение (`404`). Клиенты дополнительно блокируют повторное нажатие.
- Мобильные клиенты различают «нет сети» (повторить, показать кэш) и «сервер отказал» (показать причину)
  и не выкидывают из аккаунта при плохой связи.
